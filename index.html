Drawing notes · Why this site is a drawing set

Before anything gets built at an engineering firm, it gets drawn.

I work at HNTB, where bridges, highways and transit systems start as sets of drawings: numbered sheets, checked, marked up in red and stamped before anything is built. My part of that world sits a layer down, in the data. Schemas, pipelines and stored procedures have to be designed just as carefully before they run.

So this portfolio is built the same way, printed in cyanotype blue, the original blueprint. Each section is a sheet. The schematics show how each project is wired, not just how it looks. And the stamp at the end is yours to give.

GitHub Profile README Builder

Problem
A GitHub profile README is the first thing many reviewers see, and turning scattered public repositories into a clear story takes hours of hand-written Markdown.
What I built
Built a client-only builder that imports a public GitHub profile, lets the user pick up to eight repositories, drafts the story by hand or with optional Gemini, and composes it in three directions (Editorial, Studio, Aurora) before exporting sanitized Markdown.
Outcome
Live at gitfolio.prudhvicharan.com. No account or server needed; API keys are never stored, and tests cover README generation, security, storage and navigation.
  • React
  • TypeScript
  • Vite
  • GitHub REST API
  • Gemini API
  • react-markdown
  • rehype-sanitize
  • Vercel
Open live Source

VS Code Theme Collection

Problem
Most editor themes are built for a screenshot, not for reading code for eight hours straight.
What I built
Designed and published eight VS Code color themes, four houses in dark and light, with house colors kept to the window chrome and syntax colors tuned for long, readable sessions.
Outcome
Published on the Visual Studio Code Marketplace as prudhvicharan.four-founders, with paired dark and light themes that can follow the system appearance.
  • VS Code Theme API
  • JSON color tokens
  • Semantic highlighting
  • JavaScript
